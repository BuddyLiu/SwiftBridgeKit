# 组件接入检查表（八步法）

> 配套：`~/LINK-Workspace/桥接层研究/07_决策判据与Checklist.md`
> 原则：**契约先于实现，所有权先于同步，验证先于归档。**

---

## 第 1 步：分类（决定要不要造桥）

先过四问，**任何一问答"否"都可能意味着不该造桥**：

- [ ] Q1 SwiftUI 有原生等价物吗？（有 → 直接用原生，**停**）
- [ ] Q2 是核心竞争力 / 差异化吗？
- [ ] Q3 会 ≥2 处复用吗？（只有 1 处 → 别过度工程）
- [ ] Q4 需要精细控制（手势 / 渲染 / 布局）吗？

**产物**：一句结论。它决定了后面所有工作的正当性。

---

## 第 2 步：契约先行（纯 Swift，零 UIKit）

- [ ] 定义 `State: BridgeState`（数据 → 视图，单向）
- [ ] 定义 `Intent: BridgeIntent`（用户意图 → 业务，唯一回传）
- [ ] `Intent` 里**没有** `didLayout` / `didScroll` / `frameChanged` 这类内部副产物
- [ ] 契约层文件 **不 import UIKit**

**判据**：把 Intent 念给产品经理听，他能听懂 —— 否则说明混进了实现细节。

---

## 第 3 步：定所有权（写代码前必须定死）

- [ ] SwiftUI 是唯一 source of truth
- [ ] UIKit 视图只做「从属 + 上报」，**不自己持有一份真相**
- [ ] 画出数据流向：`State → 桥 → Intent → 业务`

违反这条 → 必然掉进循环更新路径 A/B。

---

## 第 4 步：选通道

- [ ] 需要视图层级 / 手势 / 渲染 → `UIViewRepresentable`
- [ ] 只改尺寸语义、无视图 → `Layout` 协议（iOS 16+）
- [ ] 自绘 → `Canvas` / `ShaderGraph`
- [ ] 只是外观 → 纯 SwiftUI，**别造桥**

---

## 第 5 步：写桥本体（用上四件设施）

- [ ] UIView 遵守 `BridgeView`，实现 `apply` / `teardown`
- [ ] `apply` 只做**差异映射**，不做全量重建
- [ ] 用 `BridgeHost` 包出声明式外壳
- [ ] **业务侧 import 不到任何 UIKit 类型**

---

## 第 6 步：尺寸自适应

- [ ] 异步比例走 `RatioResolver.resolve(_:)`
- [ ] `proposal` 含 `nil` / `.infinity` 时有显式翻译
- [ ] 内部约束与 proposal 冲突时，明确哪一维是 `.required`
- [ ] 比例变化时只请求一次布局（值比较）

---

## 第 7 步：验证（六条合格线，一条都不能跳）

| # | 病灶 | 验收方式 | ✅ |
|---|---|---|---|
| 1 | 尺寸 | 横竖屏 / 比例未就绪 / 就绪后 三种状态都对 | [ ] |
| 2 | 布局 | 无二次布局闪烁 | [ ] |
| 3 | 生命周期 | **反复进出页面**：无泄漏、无重复注册、退出后无日志 | [ ] |
| 4 | 状态 | **页面静置时 CPU 接近空载**（循环更新的照妖镜） | [ ] |
| 5 | 手势 | 显式声明归属，无"两侧同时识别" | [ ] |
| 6 | 性能 | 只改一个字段不引发整层重建（看 update 计数） | [ ] |

**加一个哨兵**：在 `apply` 里打印调用次数。
静置状态下数字还在涨 → 有循环，别放过。

---

## 抽模板的时机（很多团队在这里翻车）

**先有 2 座真实且合格的桥，再抽模板。**

反顺序的代价：想象出来的模板 → 带过度设计 → 兼容层自己成了新的技术债。
这就是"两次法则"：同一件事写了两次，才有资格抽象第三次。

---

## 常见做错顺序

1. ❌ 从第 5 步开始动手写 `UIViewRepresentable`
   → 没定契约和所有权，写出来的一定是 L1 且改不动。

2. ❌ 一座桥就抽模板
   → 见上。

3. ❌ 只做"能显示"，不做静置验证
   → 尺寸和手势的错看得见，循环更新看不见，但长期烧电掉帧。
   → 建议：**优先治理循环更新**，做完直接跨到 L2。

---

## 成熟度分级速查

| 等级 | 状态 |
|---|---|
| L0 | 能显示，尺寸靠硬编码 |
| L1 | 尺寸自适应正确，不会裁切 |
| L2 | 状态双向同步无循环更新，生命周期可控 |
| L3 | 有统一模板 + 通用尺寸/状态设施，新组件接入 < 半天 |
| L4 | 桥层可测试、可回归，且有"该不该造桥"的决策规范 |

> 分级是**排期工具，不是考核标准**。项目规模小的话 L2 就够，不必强推。
